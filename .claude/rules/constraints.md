# constraints.md — 制約事項・検証ルール・非機能要件

## 対称性チェック（このプロジェクト最重要ルール）

Live2D形式とスプライトセット形式は`CharacterRenderer`インターフェースで抽象化されているが、**実装時に片方だけ直して満足しやすい**（実際に本プロジェクトで2度発生した）。

- Live2D/スプライトセットのどちらかに関わる変更をしたら、**必ずもう一方の分岐も同時に確認・修正する**。
- `grep`等で、両形式に対応する要素（例: `EMOTION_STATES`の参照箇所、`Live2DRenderer`/`SpriteSetRenderer`の実装メソッド）が実際にペアで存在するかを機械的に確認してから完了とする。
- 「Live2Dだけ直した」「スプライトセットだけ直した」というコミットメッセージは書かない。両方確認した上でコミットする。
- **非対称が正当な場合もある**（例: スプライトセットの生成パイプラインはLive2Dに対応物を持たない）。その場合は「なぜ非対称でよいか」をドキュメントに明記する。黙って片方だけ書くと、実装漏れと誤読される。

`.claude/hooks/symmetry-reminder.sh`（PostToolUse）が該当ファイルの編集時にリマインドするが、**フックは補助であり判断はしない**。誤検知もあるため、必ず自分でgrepして確認する。

### 既知の非対称（詳細設計で検出済み・実装前に決着が必要）

| 内容 | 出典 |
|---|---|
| `baseResolution`がspriteset専用のため、Live2Dはモデルをロードするまでウィンドウサイズが確定しない | detailed-design/character-window.md |

## 検証ルール

### 構文・型チェック

- `.ts`/`.tsx`/`.jsx`編集後は、目視での括弧確認に頼らず機械的に確認する。`.claude/hooks/post-edit-check.sh`（PostToolUse）が`npm run typecheck`等を自動実行する。
- 手動で確認する場合は `npx esbuild <file> --outfile=/dev/null`（構文のみ・高速）または `npm run typecheck`（型・プロジェクト全体）。
- importの未使用・不足も定期的に確認する（手動レビューで見逃しやすい）。`tsconfig`は`noUnusedLocals`/`noUnusedParameters`を有効にしてある。

### 実機能確認の制約

- ElectronアプリはGUIウィンドウを要するため、**Claude Code（このサンドボックス環境）からは`npm start`等でのライブ動作確認ができない**。
- 検証は静的解析（esbuild/tsc/lint）に留め、実際の画面確認・操作確認はユーザーが手動で行う。**「動作確認済み」と自己申告しない。**
- ただし**GUIを伴わない検証は積極的に行う**。Electronのオフスクリーン実行、モックサーバー、ライブラリの実測は可能であり、詳細設計フェーズではこれで多数の設計判断を実証した（例: `AbortSignal`なしではstreamの凍結を検知できない、macOSは画面外座標を補正しない）。**推測で設計を書かない。**

## プロジェクト固有の制約

- **対応OS**: macOSのみ（v1）。
- **モデル形式**: Live2D（上級者向け）/ スプライトセット（標準の入口・おすすめ）の2種。`CharacterRenderer`で抽象化。上限は形式を問わず合計2体。
- **開発用モデルの取り扱い**: ちびキャラメーカー出力モデルは開発・検証専用。**配布物には絶対に含めない**。`dev-assets/`等、`.gitignore`対象のローカル専用ディレクトリに隔離する。
- **Chat Adapterの既定値**: 常に`mock`。`real`への切替はAPI課金が発生する操作なので、既定値を誤って変更しない。
- **セキュリティ**: ローカルサーバーは127.0.0.1限定バインド、全リクエストにトークン認証必須。この制約を緩めるような変更（0.0.0.0バインド、認証スキップ等）は行わない。
- **アプリが自分の状態について嘘をつかない**: 失敗を隠して代替物を返さない（例: real接続の失敗時にmockの固定返答へ自動フォールバックしない）。未設定の項目は未設定と表示する。

## 非機能要件

- **パフォーマンス**: 常駐時CPUは待機1〜2%、Reaction再生中も10%未満を目安。メモリ200MB前後。無操作時は描画fpsを落とす（60→15fps目安）。
- **可用性**: キャラウィンドウ/コントロールパネルの異常はClaude Code本体の動作をブロックしない。`dispatch.sh`は常に`exit 0`。ローカルサーバーのポート競合時は自動フォールバック。
- **保守性**: アダプタパターンにより新規連携先を既存コードに手を入れず追加可能。config.jsonは`schemaVersion`でマイグレーション対応。
- **ローカライズ**: v1は日本語UIのみ。
- **プライバシー**: テレメトリ・使用状況analytics・クラッシュレポートは一切収集しない。hooksイベントログは7日保持で自動削除、パーミッション0600。

## ハーネス運用に関する注意

このアプリ自体もClaude Code hooksを受信する「Code Adapter」を実装するが、これは**開発作業に使うhooks（`.claude/settings.json`）とは別物**。両者を混同しないこと。

- **開発用hooks**: このリポジトリを開発する際にClaude Codeが発火させるフック（本ハーネス）。
- **アプリ実装のhooks受信**: `dispatch.sh`経由でアプリのローカルサーバーが受け取る、**アプリの利用者側の**Claude Code hooksイベント（FR-2）。

オンボーディング（FR-14）は利用者側プロジェクトの`.claude/settings.json`にhooks設定を案内する。**実装時にこのリポジトリ自身の`.claude/settings.json`を書き換えないよう注意する。**

将来的に余裕が出たら、完成した`dispatch.sh`を自分の開発環境にも向けて、「アプリに自分の開発作業を実況させながら開発する」ドッグフーディングを検討してもよい（現時点では未着手）。
