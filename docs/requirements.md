# ヨリマシ.app 要件定義書

> 本ファイルはNotionの要件定義書のミラーです。**Notionが正本**。要件の追加・変更は必ずNotion側を先に更新し、その後本ファイルへ反映すること。
> 作成日: 2026-07-16 / 更新日: 2026-07-17(ブラウザ拡張機能連携(FR-8)・表示排他制御(FR-9)を削除、会話ペイン(FR-15)を追加)

## 1. 概要・目的

**ヨリマシ.app** は、Claude Codeでの作業実況と、Claudeとのチャット対話を、憑坐(よりまし)キャラクター「**常世灯里**(とこよ あかり)」が感情豊かに反応しながら伴走するデスクトップ常駐アプリ。

- 作業実況の擬人化(Claude Code連携)と、雑談相手(独自Chatクライアント)の2つの需要を、同一のキャラクターで満たす。
- 開発者自身のClaude Code活用基盤(ハーネスエンジニアリング)の一環と位置づける。
- デザイン方向性は電脳オカルト×HUD(和風オカルト+ターミナルUI)。たそがれ日記・MemoryTrace等の既存アプリ群とは意図的に異なる路線とし、達成バッジ等のゲーミフィケーション要素は持たせない。

## 2. 対象ユーザー・利用シーン

- **現段階**: 開発者本人のみ。Claude Codeでの日常的なコーディング作業、および claude.ai でのチャット利用の両方に寄り添うキャラクターとして使用。
- **将来配布を検討する場合**: Claude Codeを日常的に使う個人開発者・フリーランスエンジニア向けの「セットアップして使うツール」を想定(SaaS化はしない)。

## 3. 用語定義

- **Adapter**: キャラクターが連携する対象。Code Adapter(Claude Code hooks)とChat Adapter(独自Claude APIクライアント)の2種。
- **Mood / Reaction**: 感情表現の2層構造。Moodは緩やかに変化する基調、Reactionは個々のイベントで一過性に発火する反応。
- **Slot**: インストール済みモデル(Live2D/スプライトセット)の格納枠。形式を問わず最大2つまで。

## 4. 機能要件

### 4.1 アダプタ切替 (FR-1)
Code Adapter / Chat Adapterを手動で切替えられる。切替はControl Panelのホーム画面から行う。

### 4.2 Code Adapter(Claude Code連携) (FR-2)
- 検知イベント: PreToolUse, PostToolUse, PostToolUseFailure, Notification, Stop, UserPromptSubmit。
- 通信方式: hooksスクリプト(dispatch.sh) → ローカルサーバー(127.0.0.1:8765、トークン認証必須)。
- hooksは常にexit 0を返し、Claude Code本体の動作を阻害しない(非ブロッキング)。

### 4.3 Chat Adapter(独自チャットクライアント) (FR-3)
- 動作モード: mock(固定返答・無料) / real(Anthropic API実接続)。既定値はmock。
- 感情判定: mock=キーワードベース、real=キーワード or Haiku分類(将来)。
- APIキーはelectron-storeに平文保存(モック段階のリスクとして受容)。

### 4.4 感情エンジン(EmotionEngine) (FR-4)
Mood(気分・緩やか)とReaction(反応・一過性)の2層構造。優先度・クールダウン・streakベースのMood遷移を持つ。

**定義済みの全状態(計10状態)**: idle/confident/tiredの3つをMoodとし、thinking/happy/proud/worried/panic/curious/sleepyの7つをReactionとして定義する。この10状態が、FR-5(モデル管理)のマッピング対象の単一の情報源となる。

### 4.5 モデル管理 (FR-5)
モデルは**Live2D形式**と**スプライトセット形式**の2種類に対応し、共通の`CharacterRenderer`インターフェースで抽象化する(EmotionEngine側は形式を意識しない)。上限は形式を問わず合計**最大2体**。

**形式の位置づけ**
- **スプライトセット(標準の入口・おすすめ)**: 画像1枚からAI生成アシストでモーションを用意できる、敷居の低い形式。
- **Live2D(上級者向け)**: 自前でモデルを作り込みたいユーザー向け。Cubism 2/4/5両対応、フォルダ/zipドロップで取り込み(zip-slip対策あり)。

**スプライトセットの追加フロー**
1. ユーザーが静止画1枚をアップロード(透過PNG推奨)
2. アプリが自動でクロマグリーン背景に合成した画像を生成(AI不要、ローカル画像処理)
3. ユーザーがその画像を任意の外部動画生成AIサービス(Pika・Canva等、無料枠を想定)に渡し、提案プロンプトをもとに感情ごとの短い動画(mp4/webm)を生成
4. 生成された動画をアプリに取り込むと、**色キー抜き(境界連結判定つき)+アニメーションWebPへの自動変換**が行われる

**マッピング(形式共通)**: 対象はFR-4が定義する全10状態(Mood 3種+Reaction 7種)。マッピング編集画面には常に全10状態を提示し、`idle`のみ必須(他は未設定でも`idle`にフォールバック)。対応先はLive2D=モーション/表情、スプライトセット=クリップと形式ごとに異なるが、編集画面自体は対象モデルの形式に応じて自動で切り替わる。

**共通(モード連動)**: 2体セット時、「モードで自動切替」ON/OFFを選択可(形式混在も可)。ONなら各モデルをCode/Chatに割当、「入れ替える」で反転。

### 4.6 キャラクター表示ウィンドウ (FR-6)
透過・枠なし・常に最前面。ドラッグ移動、クリックスルー切替、右クリックメニュー。(マルチモニタ挙動・右クリックメニュー項目は基本設計で未確定)

**メニューバーアイコン(常設の操作面)**: クリックスルーが有効な間、キャラクターウィンドウはマウスイベントを一切受け取らないため、ドラッグ移動・右クリックメニューに到達できない(既定値は`clickThrough: true`)。この行き止まりを回避するため、macOSのメニューバーに常駐アイコンを常設し、クリックスルー切替・位置のリセット・Control Panelを開く・終了をここから常に実行できるようにする。ディスプレイ構成の変更でウィンドウが画面外に取り残された場合の復帰経路も兼ねる。

**透過は形式を問わず必須**: Live2D形式はWebGLのネイティブアルファで透過を描画。スプライトセット形式はFR-5の自動色キー抜き処理によって生成されたアルファ付きWebPで同等の透過を実現する。どちらの形式でも、ユーザーには同一の「透過したキャラクターがデスクトップに常駐する」体験を提供する。

### 4.7 コントロールパネル (FR-7)
独立Electronアプリ。画面: ホーム/モデル管理/モード設定/全体設定/ログ/権利情報の6タブ構成。

### 4.10 設定管理(config.json) (FR-10)
Zodスキーマでバリデーション。`schemaVersion`によるマイグレーション対応。real系フィールドは全部安全なデフォルト値。

### 4.11 ログ管理 (FR-11)
hooksイベントログはファイルパス・プロジェクト名を含めて7日保持で自動削除。共有用にプロジェクト名を仮名化したエクスポート機能あり(生ログは非マスクのまま保持)。

### 4.12 権利情報表示 (FR-12)
Control Panel内に常設タブ。Live2D利用区分(Live2D形式のみ対象)、**外部動画生成AIサービスのToS注意(スプライトセット形式のみ対象)**、使用OSSライセンス一覧(ビルド時自動生成)、フォントライセンス、持ち込みモデルの著作権注意書き、Anthropic API利用に関する注記を表示。

### 4.13 セキュリティ機構 (FR-13)
127.0.0.1限定バインド、トークン認証(HTTP+WS)、`frame-ancestors`によるCSP制限、`contextIsolation: true`、パストラバーサル対策。

### 4.14 オンボーディング (FR-14)
ようこそ画面 → モデルインポート誘導 → モード選択 → 完了、の4ステップ。各画面の詳細は基本設計で未確定。

### 4.15 会話ペイン (FR-15)
Chat Adapter(FR-3)でのユーザーとキャラクターの対話に使うUI。**Control Panelと同一ウィンドウ内の左側ペイン**として実装し、右側にControl Panelの6タブが並ぶ(別ウィンドウにしない)。**既定では会話ペインとControl Panelの両方が展開した状態**。ペインの縁にあるタブ(つまみ)で会話ペインを折りたたみ/展開でき、折りたたむとControl Panelのみになる。ユーザーのメッセージ入力、Claudeの応答表示(履歴・streaming表示)を行う。画面の詳細は詳細設計で確定する。

**会話履歴はv1では永続化しない**(メモリのみ。ウィンドウを閉じたら消える)。保持期間・パーミッション・削除UIを定義しないまま機微な会話内容を永続化しないため(hooksログはC-03で明示的に決めているが、チャット履歴には同等の判断がない)。

## 5. 対象プラットフォーム・技術スタック

- **対応OS**: macOSのみ(v1)。
- **デスクトップアプリ**: Electron + TypeScript + React + Vite。
- **Live2D描画**: PixiJS + pixi-live2d-display(Cubism 2/4/5両対応)。
- **設定バリデーション**: Zod。
- **ローカルサーバー**: Node.js(http + ws)、127.0.0.1:8765。
- **Chat Adapter実装**: `@anthropic-ai/sdk`(公式SDK)をMainプロセスで使用。リトライはSDK標準機構に任せ、冷えた(進行が止まった)streamの検知は無通信ウォッチドッグ(`AbortSignal`)を別途実装する(SDKの`timeout`は応答ヘッダ受信までしかカバーしないため)。
- **モデル描画抽象化**: `CharacterRenderer`インターフェースでLive2D/スプライトセットを共通の呼び出し形に統一。
- **スプライトセット処理**: クロマキー合成・色キー抜き(境界連結判定)・アニメーションWebPエンコードをローカルで実行(具体的な画像処理ライブラリは詳細設計で選定)。
- **配色テーマ**: `THEMES`オブジェクトによるトークン管理。light(白望)/dark(漆黒)/system(OS連動、`prefers-color-scheme`検知)の3モード。

## 6. 非機能要件

- **パフォーマンス**: 常駐時CPUは待機1〜2%、Reaction再生中も10%未満を目安。メモリ200MB前後。無操作時は描画fpsを落とす。
- **可用性**: キャラウィンドウ/コントロールパネルの異常はClaude Code本体の動作をブロックしない。ローカルサーバーポート競合時は自動フォールバック。
- **保守性**: アダプタパターンにより新規連携先を既存コードに手を入れず追加可能。config.jsonは`schemaVersion`でマイグレーション対応。
- **互換性**: Live2D Cubism 2/4/5両対応。Claude Code hooks仕様変更への追従方針は未確定。
- **ローカライズ**: v1は日本語UIのみ。
- **アップデート**: 手動更新のみ。自動アップデート機構は配布フェーズで検討。

## 7. セキュリティ要件

1. ローカルサーバーは127.0.0.1限定バインド。
2. 全リクエスト(HTTP+WS)にトークン認証を必須化。
3. 全レンダラーで`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
4. アーカイブ展開時のパストラバーサル検証を必須化(zip-slip対策)。

## 8. データ・プライバシー

- hooksイベントログはファイルパス・プロジェクト名を含めて7日保持で自動削除。パーミッション0600。
- 共有・デバッグ目的のエクスポート機能はパスを仮名化(project-a/project-b)して書き出す。生ログは非マスクのまま保持。
- Notion連携はドキュメント内容のみ送信。ランタイムデータ(hooksログ・チャット履歴)は送らない。
- Obsidian連携はローカルVaultのみ、外部送信なし。
- テレメトリ・使用状況analytics・クラッシュレポートは一切収集しない。
- ローカル保存データの暗号化はOS側(FileVault)に委ね、アプリ側では実施しない。
- APIキーはelectron-storeに平文保存(モック段階のリスクとして受容)。

## 9. 権利関係

- **Live2D Cubism SDK/Core**: 個人・小規模事業者(年商1,000万円未満)は契約・費用免除。ただし本アプリは「AI/チャットボットのインターフェース」に該当しうるため、**配布前にLive2D公式の判定フローを必ず確認する**(Expandable Applicationの可能性)。**この確認はLive2D形式のモデルスロットにのみ関係し、スプライトセット形式には及ばない。**
- **外部動画生成AIサービス(スプライトセット用)**: Pika・Canva等の無料枠は一般的に個人利用限定。配布時は各サービスの利用規約(商用利用可否)を確認する。生成物の著作権・利用範囲もサービスごとに異なるため、ユーザー自身の責任で選択・利用する。
- **OSSライセンス**: Electron/PixiJS/pixi-live2d-display/React/Zod/lucide-react等はMIT/ISC中心。配布時は`license-checker`で自動収集し、NOTICEとして同梱。
- **フォント**: Zen Antique / M PLUS 1 Code / JetBrains MonoはGoogle Fonts経由、SIL Open Font License 1.1。
- **ユーザーが追加するLive2Dモデル**: 著作権はモデルの作成者・追加した本人に帰属。アプリはモデルを一切同梱しない。
- **開発中のモック用モデル**: ちびキャラメーカー出力モデルを使用。**配布物には絶対に含めない**(dev-assets等、.gitignore対象のローカル専用ディレクトリに隔離)。
- **Anthropic API**: 利用者自身のAPIキーで呼び出し、Anthropicの利用規約が適用される。配布時は第三者に「Claudeを呼ぶアプリ」を配る形になるため、利用規約上問題ないか要確認。

## 10. スコープ外(v1)

- Windows/Linux対応
- 多言語UI
- Live2Dモデルの自作機能(Cubism Editor相当の機能は持たない)
- 複数ユーザー間の共有・SaaS的バックエンド
- クラウド同期(config/ログの端末間同期)
- 自動アップデート機構
- Chat Adapterのagentic機能(ツール呼び出し等)
- **音声(TTS)** — 将来検討事項として保留。v1はテキスト+アニメーションのみ。

## 11. 制約条件

- **開発体制**: フリーランス個人開発、単独。
- **予算**: 個人利用段階は原則¥0。
- **優先度**: たそがれ日記等の既存ロードマップと同等。並行進行。
- **開発ペース**: 1日1〜2時間(たそがれ日記と同一ペース)。
- **並行タスク**: たそがれ日記の設計進行、関東圏転職活動と時間を取り合う関係にある。
- **転居予定**: 2026年9月の引越し前後は両プロジェクトとも進行速度が落ちる可能性を織り込む。
- **対応OS**: macOSのみ。
